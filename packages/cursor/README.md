# Cursor Cloud Agent GPG Commit Signing

Guide for configuring GPG commit signing on Cursor Cloud Agents. Cloud agents run on ephemeral remote VMs without access to your local GPG key. This package provides scripts that automatically import your key, cache the passphrase, and configure git signing during the cloud agent install step.

## How It Works

```text
Cloud Agent Boot
  → .cursor/environment.json "install" hook runs
    → Downloads setup.sh from this package
      → Downloads and runs init-gpg.sh
        → Imports GPG private key from base64-encoded Cursor secret
        → Extracts git identity from the key (or from secrets if provided)
        → Presets passphrase into gpg-agent (if passphrase-protected)
        → Configures git to sign all commits
      → Clears all GPG secrets from the environment
    → Runs project-specific install (.cursor/scripts/install.sh)
  → Agent starts working — all commits are GPG-signed
```

## Setup

### Step 1: Generate a GPG Key

Run the helper script to generate a dedicated key for cloud agents. It uses your existing `git config --global user.email` and `user.name` automatically:

```bash
./packages/cursor/generate-key.sh
```

To use a different email or name (e.g., your GitHub noreply address):

```bash
./packages/cursor/generate-key.sh --email "ID+user@users.noreply.github.com" --name "Your Name"
```

The script outputs two things:

- **Public key** → paste into [GitHub GPG keys](https://github.com/settings/keys)
- **`GPG_PRIVATE_KEY_BASE64`** → paste into Cursor secrets (Step 2)

The generated key is passwordless — no `GPG_PRIVATE_KEY_PASSPHRASE` secret needed.

To create a key manually instead (e.g., with a passphrase):

```bash
# Create an ed25519 signing key that expires in 1 year (use 0 for no expiry)
gpg --quick-generate-key "Your Name <ID+user@users.noreply.github.com>" ed25519 sign 1y

# Export as base64 for Cursor secrets:
gpg --armor --export-secret-keys KEY_ID | base64 | tr -d '\n'

# Export the public key for GitHub:
gpg --armor --export KEY_ID
```

### Step 2: Configure Your Local Machine (if not already done)

If you already have `commit.gpgsign = true` in your git config and GPG signing works locally, skip this step.

Install GPG if not already installed:

```bash
brew install gnupg
```

Configure git to sign commits:

```bash
git config --global commit.gpgsign true
git config --global user.signingkey YOUR_KEY_ID
```

Ensure your `~/.gnupg/gpg.conf` has:

```ini
pinentry-mode loopback
```

And your shell profile (`~/.zshrc` or `~/.bashrc`) exports:

```bash
export GPG_TTY=$(tty)
```

Restart your gpg-agent after changes:

```bash
gpgconf --kill gpg-agent
```

### Step 3: Add Cursor Secrets

Go to [Cursor Settings → Cloud Agent → Secrets](https://cursor.com/dashboard?tab=cloud-agents).

| Secret | Required | Description |
| --- | --- | --- |
| `GPG_PRIVATE_KEY_BASE64` | Yes | Output from `generate-key.sh` or manual base64 export |
| `GPG_PRIVATE_KEY_PASSPHRASE` | Only if key has a passphrase | Not needed for keys generated by `generate-key.sh` |
| `MY_GIT_EMAIL` | No | Overrides the email embedded in the key UID |
| `MY_FULL_NAME` | No | Overrides the name embedded in the key UID |

Your project may require additional environment variables (e.g., private registry credentials). Check with your team for any team-level secrets that should already be configured.

### Step 4: Verify

1. Launch a Cloud Agent task
2. Check logs for `[GPG] Signing configured successfully`
3. After the agent pushes, check the commit on GitHub for the **Verified** badge

For Linear integration: link your Cursor account in [Linear Settings → Integrations → Cursor](https://linear.app/settings/integrations/cursor).

## Project Integration

To enable GPG signing in a new project, add a [`.cursor/environment.json`](https://github.com/spear-ai/citizen/blob/main/.cursor/environment.json) file. The `install` command should start with the GPG setup prefix (which downloads and sources `setup.sh`), followed by your project's install commands.

`SCRIPT_DOWNLOAD_ROOT_URL` should already be configured as a team-level Cursor secret. If it is not set, the GPG setup is skipped — local development is unaffected, but cloud agent commits will not be signed. If the scripts are hosted in a private repository, set `GITHUB_SCRIPTS_TOKEN` to a [fine-grained GitHub personal access token](https://github.com/settings/personal-access-tokens) with `Contents: Read-only` permission scoped to the scripts repository.

The `environment.json` includes a SHA-256 checksum of `setup.sh` for integrity verification. If `setup.sh` is updated, regenerate the checksum and update each project's `environment.json`:

```bash
sha256sum packages/cursor/setup.sh
```

For projects with complex setup or multiple install steps, move the project-specific commands into a separate script (e.g., [`.cursor/scripts/install.sh`](https://github.com/spear-ai/citizen/blob/main/.cursor/scripts/install.sh)) and source it from the `install` hook. This keeps `environment.json` readable and the install logic maintainable.

**Note:** The `install` hook runs in a clean shell with only Cursor secrets available — no `.env` files or shell profiles are sourced. If your project requires environment variables for package installation (e.g., private registry URLs, authentication tokens), these must be configured as Cursor secrets (team-level or per-developer) for the cloud agent setup to succeed.
